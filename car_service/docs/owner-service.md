# Сервис владельцев автомобилей

`OwnerService` управляет владельцами автомобилей: создаёт записи, ищет и обновляет их, удаляет и восстанавливает. Контракт методов описан в [OwnerService.java](../src/main/java/com/example/car_service/service/OwnerService.java), HTTP API — в [OwnerController.java](../src/main/java/com/example/car_service/controller/OwnerController.java).

## HTTP API

Базовый путь: `/api/v1/owners`. В локальной конфигурации адрес сервера — `http://localhost:8080`. Тела запросов и ответов передаются в JSON; `{id}` — UUID владельца.

| Метод | Путь относительно базового | Действие | Успешный ответ |
| --- | --- | --- | --- |
| `POST` | — | Создать владельца | `201 Created`, `OwnerResponse` |
| `GET` | — | Найти активных владельцев | `200 OK`, `OwnerPageResponse` |
| `GET` | `/{id}` | Получить активного владельца | `200 OK`, `OwnerResponse` |
| `PATCH` | `/{id}` | Частично обновить активного владельца | `200 OK`, `OwnerResponse` |
| `DELETE` | `/{id}` | Мягко удалить владельца | `204 No Content`, без тела |
| `DELETE` | `/{id}/admin` | Физически удалить владельца | `204 No Content`, без тела |
| `PATCH` | `/{id}/restore` | Восстановить мягко удалённого владельца | `204 No Content`, без тела |

`OwnerResponse` содержит `id`, `fullName`, `phone`, `email`, `cars`, `createdAt`, `updatedAt`. Даты владельца имеют формат `HH:mm - dd.MM.yyyy`, например `14:30 - 16.09.2026`. У нового владельца `cars` — пустой массив. Вложенные автомобили представлены сокращённой моделью [CarSummaryResponse](../src/main/java/com/example/car_service/domain/dto/car/CarSummaryResponse.java), а не полной моделью `CarResponse`. Она содержит только `id`, `vin`, `regNumber`, `manufacturer` и `model`, без обратной ссылки на владельца, пробега, дат и списка обслуживаний.

`OwnerPageResponse` содержит массив `owners`, номер страницы `page`, размер страницы `size`, общее количество подходящих владельцев `totalElements` и страниц `totalPages`. Поиск без совпадений возвращает `200` и пустой массив `owners`.

## Правила работы

- Мягкое удаление сохраняет запись и устанавливает дату удаления. Владелец исчезает из поиска, а чтение и обновление по ID возвращают `404`.
- Оба способа удаления запрещены, если у владельца есть связанные автомобили: ответ `409`.
- Повторное мягкое удаление возвращает `409`.
- Восстановление доступно только для мягко удалённой записи. Попытка восстановить активного владельца возвращает `409`.
- Физическое удаление доступно для активной и мягко удалённой записи. После него чтение, обновление, удаление и восстановление по прежнему ID возвращают `404`.
- Суффикс `/admin` обозначает маршрут физического удаления; проверка роли администратора в текущем приложении не реализована.
- Обновление меняет только ФИО, телефон и email. Пропущенные поля и поля со значением `null` сохраняют прежние значения. Пустой объект `{}` допустим. Изменение связей с автомобилями через этот API не предусмотрено.

## Валидация

При создании все три поля обязательны. При обновлении проверяются только переданные значения, отличные от `null`.

| Поле | Ограничения |
| --- | --- |
| `fullName` | От 2 до 100 символов; пустая строка и строка только из пробелов недопустимы |
| `phone` | Ровно 11 цифр, первая — `7`; например `79991234567`. Знак `+`, пробелы и дефисы недопустимы |
| `email` | Непустой адрес, соответствующий проверке `@Email` |

Валидация DTO вызывается контроллером через `@Valid`. Сам интерфейс сервиса не запускает её при прямом вызове из другого Java-кода.

## Поиск, сортировка и пагинация

Все параметры передаются в query string и необязательны. Разные фильтры объединяются условием «И».

| Параметр | Поведение |
| --- | --- |
| `fullName` | Поиск части ФИО без учёта регистра. Пробелы по краям убираются; пустой фильтр игнорируется. `%`, `_` и `\` считаются обычными символами |
| `owners` | Точное совпадение ФИО с одним из переданных значений; несколько значений можно передать повторением параметра: `owners=Alice&owners=Bob` |
| `phone` | Точное совпадение; формат такой же, как при создании |
| `email` | Точное совпадение; адрес должен быть непустым и проходить `@Email` |
| `createdFrom`, `createdTo` | Границы даты создания в формате `YYYY-MM-DD` |
| `updatedFrom`, `updatedTo` | Границы даты обновления в формате `YYYY-MM-DD` |
| `page` | Номер страницы с нуля; если отсутствует или отрицательный, используется `0` |
| `size` | Размер страницы от `1` до `100`; если отсутствует или выходит за диапазон, используется `20` |
| `sortBy` | `fullName`, `phone`, `email` или `updatedAt`; если отсутствует или пустой, используется `fullName` |
| `direction` | `asc` или `desc`, без учёта регистра; если отсутствует или пустой, используется `asc` |

Каждая граница даты работает отдельно. Начальный и конечный дни включаются целиком в часовом поясе сервера. Будущие даты запрещены. Обратный диапазон (`from` позже `to`) отдельно не валидируется и даёт пустую выборку. Неподдерживаемые значения `sortBy` и `direction` возвращают `400`.

## Примеры запросов

### Создать владельца

```http
POST /api/v1/owners HTTP/1.1
Host: localhost:8080
Content-Type: application/json

{
  "fullName": "Алексей Петров",
  "phone": "79991234567",
  "email": "alex@example.com"
}
```

Пример тела ответа `201 Created`:

```json
{
  "id": "7b03c724-8f0f-449e-b89a-7b6f632bd960",
  "fullName": "Алексей Петров",
  "phone": "79991234567",
  "email": "alex@example.com",
  "cars": [],
  "createdAt": "14:30 - 16.09.2026",
  "updatedAt": "14:30 - 16.09.2026"
}
```

Идентификатор и даты формируются сервером. В следующем запросе подставьте `id` из своего ответа.

### Частично обновить владельца

```http
PATCH /api/v1/owners/7b03c724-8f0f-449e-b89a-7b6f632bd960 HTTP/1.1
Host: localhost:8080
Content-Type: application/json

{
  "phone": "79991234568",
  "email": null
}
```

Ответ — `200 OK` с обновлённым `OwnerResponse`. Телефон изменится; email и пропущенное ФИО сохранят прежние значения.

### Найти владельцев

```http
GET /api/v1/owners?phone=79991234568&sortBy=updatedAt&direction=desc&page=0&size=10 HTTP/1.1
Host: localhost:8080
```

Ответ — `200 OK` с `OwnerPageResponse`: первая страница активных владельцев с указанным телефоном, отсортированных по дате обновления от новых к старым.

## Ошибки

| HTTP-статус | Причина |
| --- | --- |
| `400 Bad Request` | Ошибка валидации DTO, некорректный UUID, JSON или тип параметра |
| `404 Not Found` | `OwnerNotFoundException`: запись отсутствует либо мягко удалена при чтении или обновлении |
| `409 Conflict` | `OwnerConflictException`: удаление владельца с автомобилями, повторное мягкое удаление или восстановление активного владельца |
| `500 Internal Server Error` | Внутренняя ошибка; в частности, `OwnerBusinessException` при ошибке доступа к БД во время создания |

[GlobalExceptionHandler](../src/main/java/com/example/car_service/exception/GlobalExceptionHandler.java) возвращает `ErrorDto` для трёх указанных исключений сервиса и `MethodArgumentNotValidException` при валидации DTO. Поле `statusCode` содержит HTTP-статус, `message` — описание ошибки. Например, при попытке удалить владельца с автомобилями:

```json
{
  "statusCode": 409,
  "message": "Owner with linked cars cannot be deleted"
}
```

Для ошибок, не охваченных этим обработчиком, включая некорректный JSON или UUID, тело формирует Spring Boot, и его структура может отличаться от `ErrorDto`.
