# Car API

Контракт текущей реализации. Базовый URL: `http://localhost:8080/api/v1/cars`. JSON; `{id}` — UUID автомобиля. Перед созданием нужен активный владелец из [Owner API](owner-service.md).

## Операции

| Метод | Путь относительно базового | Действие | Успех |
| --- | --- | --- | --- |
| POST | `/` | Создать автомобиль | `201` + CarResponse |
| GET | `/` | Поиск активных автомобилей | `200` + CarPageResponse |
| GET | `/{id}` | Получить активный автомобиль | `200` + CarResponse |
| PATCH | `/{id}` | Обновить активный автомобиль | `200` + CarResponse |
| DELETE | `/{id}` | Мягко удалить | `204`, без тела |
| DELETE | `/{id}/admin` | Удалить автомобиль и историю работ | `204`, без тела |
| PATCH | `/{id}/restore` | Восстановить | `204`, без тела |

В строках `/` используется сам базовый URL без завершающего слеша. `/admin` не обеспечивает проверку роли: авторизация пока не реализована.

## Данные и правила

При создании обязательны все поля, кроме `regNumber`. В PATCH отсутствие поля и `null` сохраняют прежнее значение; `{}` и объект только с `null` дают `400`. Очистка поля через `null` не предусмотрена.

| Поле | Ограничения |
| --- | --- |
| `vin` | 17 латинских букв/цифр без `I`, `O`, `Q` и пробелов; сохраняется в верхнем регистре. В PATCH отсутствует |
| `regNumber` | До 20 символов, не пустая строка и не только пробелы; при создании допускается `null` |
| `year` | Целое от 1886 до текущего года сервера; ниже минимума → `400`, будущий год → `409` |
| `mileage` | Неотрицательное целое; уменьшение при обновлении → `409`, прежнее значение допустимо |
| `manufacturer`, `model` | Непустые строки до 100 символов, не только пробелы |
| `ownerId` | UUID существующего активного владельца; смена владельца разрешена |

При сохранении строки не обрезаются; нормализуется только регистр VIN. Служебные поля не входят в DTO записи.

| Сценарий | Поведение |
| --- | --- |
| Занятый VIN | Предварительная проверка без учёта регистра → `409`; удалённая мягко запись тоже занимает VIN |
| Soft delete | Сохраняет автомобиль и работы; поиск исключает запись, GET/PATCH по ID дают `404` |
| Повторный soft delete / restore активной записи | `409` |
| Restore | Очищает `deletedAt`, только если владелец активен; иначе `404` |
| Hard delete | Удаляет активный или мягко удалённый автомобиль вместе со всеми работами; владелец и центры сохраняются |
| После hard delete | Восстановление невозможно, VIN освобождается, прежний ID даёт `404` |

Каскад удаления работ настроен в JPA; прямой SQL DELETE его не запускает.

## Поиск

Query-параметры необязательны, разные фильтры объединяются через `AND`. Результат содержит только активные автомобили.

| Параметр | Правило |
| --- | --- |
| `vin` | Полное совпадение без учёта регистра; формат как при создании |
| `regNumber` | Точное совпадение без нормализации; до 20 символов |
| `manufacturer`, `model` | Часть строки без учёта регистра; края фильтра обрезаются; `%`, `_`, `\` — обычные символы |
| `ownerId` | Точное совпадение UUID; неизвестный ID даёт пустую выборку |
| `yearFrom`, `yearTo` | Независимые включительные границы, не меньше 1886; будущий год в фильтре допустим |
| `mileageFrom`, `mileageTo` | Независимые включительные неотрицательные границы |
| `page` | С нуля, по умолчанию `0`; отрицательное значение → `400` |
| `size` | 1–100, по умолчанию `20`; выход за диапазон → `400` |
| `sortBy` | `vin`, `regNumber`, `year`, `mileage`, `manufacturer`, `model`, `createdAt`, `updatedAt`; по умолчанию `model` |
| `direction` | `asc`/`desc`, регистр неважен; по умолчанию `asc` |

Пустые строковые фильтры, обратные диапазоны и неподдерживаемая сортировка дают `400`. Значения по умолчанию применяются к `null`, ошибочные числа не заменяются. Порядок записей с одинаковым значением сортировки не гарантирован.

## Ответы

| Модель | Поля |
| --- | --- |
| CarResponse | `id`, `vin`, `regNumber`, `year`, `mileage`, `manufacturer`, `model`, `ownerId`, `createdAt`, `updatedAt` |
| CarPageResponse | `cars` (массив CarResponse), `page`, `size`, `totalElements`, `totalPages` |

Даты — ISO 8601 с часовым смещением, например `2026-09-30T12:00:00Z`. ID и даты формирует сервер. Ответ не содержит entity владельца, историю работ или `deletedAt`. `size` — запрошенный размер страницы; `totalElements` — количество всех совпадений. Поиск без совпадений: `200`, `cars: []`, `totalElements: 0`, `totalPages: 0`.

## Примеры

Тело `POST /api/v1/cars` с `Content-Type: application/json`; замените `ownerId` реальным ID активного владельца:

```json
{
  "vin": "1hgcm82633a004352",
  "regNumber": "AB123CD",
  "year": 2003,
  "mileage": 150000,
  "manufacturer": "Honda",
  "model": "Accord",
  "ownerId": "7b03c724-8f0f-449e-b89a-7b6f632bd960"
}
```

Тело `PATCH /api/v1/cars/{id}` — увеличивает пробег, сохраняет госномер:

```json
{"mileage":151000,"regNumber":null}
```

Поиск: `GET /api/v1/cars?manufacturer=hon&yearTo=2020&sortBy=updatedAt&direction=desc&page=0&size=10`.

## Ошибки и ограничения

| Статус | Причины |
| --- | --- |
| `400` | Невалидные DTO/параметры, пустой PATCH, некорректный JSON или UUID |
| `404` | Автомобиль отсутствует или удалён при GET/PATCH; владелец отсутствует/неактивен при создании, переназначении или restore |
| `409` | Занятый VIN, уменьшение пробега, будущий год, повторный soft delete, restore активной записи |
| `500` | Ошибка БД или другая внутренняя ошибка |

Доменные исключения и `MethodArgumentNotValidException` возвращают ErrorDto, например:

```json
{"statusCode":409,"message":"Пробег автомобиля нельзя уменьшить"}
```

При двух одновременных созданиях одного VIN БД не допустит дубликат, но второе сохранение пока может дать `500` вместо `409`. Единой обработки всех ошибок БД нет. Для некорректного JSON/UUID и необработанных ошибок формат ответа может отличаться. Ошибки валидации пока содержат технический `e.getMessage()`. DTO-валидация запускается через `@Valid` в контроллере, не при прямом вызове сервиса.
