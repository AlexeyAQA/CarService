# История обслуживания

`GET /api/v1/cars/{carId}/maintenance-records`

Возвращает историю существующего активного автомобиля. Все фильтры необязательные и объединяются через AND. Фильтрация выполняется в БД до пагинации.

| Параметр | Формат и поведение |
| --- | --- |
| `dateFrom` | Дата обслуживания от, включительно; `yyyy-MM-dd` |
| `dateTo` | Дата обслуживания до, включительно; `yyyy-MM-dd` |
| `performerType` | `SELF` или `SERVICE_CENTER` |
| `serviceCenterId` | UUID центра; можно передать без `performerType` |
| `q` | Подстрока в названии позиции или PN, без учёта регистра; максимум 255 символов после обрезки краёв. Пустой/пробельный текст игнорируется. `%`, `_` и `\` ищутся буквально |
| `page` | Номер страницы от 0; по умолчанию 0 |
| `size` | Размер страницы 1–100; по умолчанию 5 |

Сортировка фиксированная: `serviceDate DESC, id DESC`. Ответ содержит `records`, `page`, `size`, `totalElements`, `totalPages`. Количества относятся к отфильтрованной истории. Нет совпадений — `200` с пустым `records`.

Поиск `q` отбирает целые записи: в каждой возвращаются все позиции и полная сумма, даже если совпала только одна позиция. Несколько совпавших позиций не дублируют запись.

`400`: неверный формат параметров, недопустимая пагинация, `dateFrom > dateTo`, либо сочетание `SELF` и `serviceCenterId`. `404`: автомобиль отсутствует или мягко удалён. Неизвестный, но корректный UUID центра в фильтре даёт пустую историю.

Пример:

```http
GET /api/v1/cars/{carId}/maintenance-records?dateFrom=2026-01-01&dateTo=2026-10-31&performerType=SERVICE_CENTER&q=OC47&page=0&size=5
```

Без параметров возвращается первая страница всей истории. При изменении фильтров клиент должен сбрасывать `page` на 0.

Одна запись: `GET /api/v1/cars/{carId}/maintenance-records/{recordId}`. Возвращает `200` с `MaintenanceRecordResponse`; `404`, если автомобиль неактивен/отсутствует либо запись не найдена у этого автомобиля.
