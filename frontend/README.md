# Сервисная книжка — frontend

Локальный интерфейс к Java/Spring-проекту. Дизайн основан на предоставленных макетах: тёмная навигация, светлая рабочая область, жёлтые основные действия. Backend в рамках этой работы не изменён.

## Запуск

Нужны Node.js 22.12+ и pnpm 11.25.0. Зависимости зафиксированы в `pnpm-lock.yaml`.

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Открыть **http://127.0.0.1:5173**. На этой машине зависимости уже установлены. Для быстрого запуска из Проводника предусмотрен `start.cmd`: он использует установленный Node либо bundled Node приложения Codex. Это вспомогательный локальный launcher; обычный способ запуска — команды выше.

```powershell
pnpm build      # TypeScript + production build в dist/
pnpm preview    # просмотр production build, порт 4173
pnpm typecheck  # только проверка типов
```

## Почему этот стек

| Решение | Назначение |
| --- | --- |
| React 19 + TypeScript | Компоненты интерфейса и типизированные DTO, согласованные с Java |
| Vite 8 | Быстрая локальная разработка, сборка статического SPA, proxy к Spring |
| React Router 7 | Адреса страниц, кнопки назад, переходы к автомобилю и записи |
| TanStack Query 5 | Загрузка, состояния ошибок, кеш и обновление после сохранения |
| React Hook Form 7 + Zod 4 | Динамические позиции записи и проверки формы перед запросом |
| Lucide + локальный Manrope | Единые иконки и кириллица без внешнего сервиса шрифтов |
| Обычный CSS с переменными | Оформление под макеты и адаптация к узкому экрану |

Это приложение для работы с данными, а Spring уже выполняет серверную часть. Для текущего объёма достаточно браузерного SPA. SSR, второй backend и глобальное хранилище Redux не нужны. Страницы загружаются отдельными чанками. При появлении публичных SEO-страниц или серверного рендеринга архитектуру стоит пересмотреть.

Основание выбора: [React — сборка приложения с Vite](https://react.dev/learn/build-a-react-app-from-scratch), [Vite — требования и запуск](https://vite.dev/guide/), [TanStack Query — работа с серверными данными](https://tanstack.com/query/latest/docs/framework/react/overview), [React Router — declarative mode](https://reactrouter.com/start/declarative/installation).

## Два режима

Переключение: **Настройки → Режим работы**. По умолчанию включена демонстрация. Режим виден в шапке. Демо никогда не используется как автоматическая замена упавшему API.

| Возможность | Демонстрация | Мой сервер |
| --- | --- | --- |
| Гараж, поиск по марке, пагинация | Да | `GET /api/v1/cars` |
| Карточка автомобиля | Да | `GET /api/v1/cars/{id}` |
| Добавить / изменить автомобиль | Да | POST / PATCH cars |
| Убрать автомобиль из гаража | Да, мягкое удаление | DELETE cars/{id}, мягкое удаление |
| Выбрать / создать владельца | Да | GET / POST owners |
| Создать запись обслуживания | Да | POST cars/{id}/maintenance-records |
| Полная история, детали, фильтр по работе/PN | Да | Ожидает API чтения записей |
| Список и создание центров | Да | Ожидает API центров |
| Плановое ТО | Демонстрационный пример | Не реализовано |
| Документы, вход, фото автомобилей | Документы обозначены как будущая функция; фото демонстрационное | API отсутствует |

Демоданные хранятся в localStorage под ключом `service-book:demo:v1`; предпочтение режима — `service-book-mode`. Они доступны только в том же браузере и origin. `localhost` и `127.0.0.1` — разные origin, как и разные порты. Исходные примеры можно восстановить в настройках с подтверждением; это удалит изменения только деморежима. Ошибка localStorage не маскируется успешным сохранением.

В режиме API приложение не подмешивает демоисторию. После создания записи её ответ показывается из кеша текущей вкладки. Перезагрузка убирает этот кеш; запись остаётся на backend, но снова получить её можно будет после добавления GET. SERVICE_CENTER пока задаётся существующим UUID, SELF работает без центра. Создавать центры на backend пользователь продолжает в своём учебном процессе.

## Подключение Spring

Vite перенаправляет `/api` на `http://localhost:8080`. Это избавляет локальную разработку от необходимости менять CORS на backend. Другой адрес задаётся в `.env.local` через `API_PROXY_TARGET`; пример — `.env.example`. После изменения перезапустите Vite.

Для production раздавайте `dist/` через сервер с SPA fallback на `index.html`, а `/api` проксируйте к Spring. `vite preview` — локальный просмотр сборки, не production-сервер.

На backend используется H2 в памяти: после его перезапуска реальные владельцы и автомобили могут исчезнуть. Фронтенд не создаёт тестовые объекты на сервере автоматически. Авторизации пока нет; карточка профиля в шапке ведёт в настройки и не означает, что пользователь вошёл.

## Структура

```text
src/
  data/           DTO, демоданные, единый gateway demo/API
  components/     формы, диалоги, таблица истории
  pages/          гараж, автомобиль, новая запись, детали, настройки
  lib/            форматирование дат, сумм, пробега
  app-context.tsx режим и уведомления
  styles.css      дизайн и адаптивные размеры
```

Gateway повторяет фактические поля Java DTO (`manufacturer`, `regNumber`, `year`, `ownerId`). Новые серверные методы подключаются здесь, не требуют переписывать форму. Общий поисковый параметр `q` не выдуман: поиск гаража отправляет поддерживаемый `manufacturer`.

## Особенности формы

- Дата не в будущем, пробег — целое неотрицательное число, минимум одна позиция.
- PN виден только для PART: края обрезаются, пустое значение становится null. Для WORK всегда отправляется null.
- Промежуточная сумма считается в целых копейках (BigInt), итог ответа — серверный.
- Практический предел суммы позиции в интерфейсе — 999 999 999,99 ₽, ниже DECIMAL(19,2), чтобы JSON number сохранял копейки.
- Добавление записи не меняет текущий пробег авто — так же работает текущий Java-сервис.
- У PATCH автомобиля VIN неизменяемый; уменьшать пробег нельзя; очистка госномера не предлагается, поскольку null на backend означает «не менять».
- Файлы и напоминания не имитируют сохранение на backend. Фото Renault и условия его использования описаны в `public/images/SOURCES.md`.

Автотесты не добавлены по текущей договорённости. Локальная сборка проверяет типы; основные сценарии дополнительно проверены через интерфейс браузера. Запросы на создание данных в Spring в этой работе не выполнялись.
