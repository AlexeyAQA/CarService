# Сервисная книжка — frontend

Интерфейс работает только с Java/Spring API. Данные из браузерного деморежима не читаются и на сервер не переносятся. Ошибка подключения отображается явно.

## Запуск

1. Запустите `CarServiceApplication` в IDEA (по умолчанию порт 8080).
2. Откройте `frontend/start.cmd` или выполните команды ниже.
3. Откройте http://127.0.0.1:5173. Выбирать режим в настройках больше не нужно.

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Нужны Node.js 22.12+ и pnpm 11.25.0. Если зависимости уже установлены, повторная установка не нужна. `start.cmd` использует Node из PATH или доступный на этой машине runtime Codex. Окно консоли оставьте открытым; остановка — Ctrl+C.

Vite перенаправляет `/api` на `http://localhost:8080`. Другой адрес задаётся в `.env.local` через `API_PROXY_TARGET` (пример — `.env.example`); после изменения перезапустите Vite. В настройках приложения есть проверка соединения.

**База backend сейчас H2 в памяти:** после остановки Spring данные исчезают. Для постоянного хранения нужна отдельная настройка backend. Фронт не создаёт примеры автоматически и не сохраняет записи в localStorage.

## Подключённые API

| Экран / действие | API |
| --- | --- |
| Гараж: поиск по марке, страницы | `GET /api/v1/cars?manufacturer=...&page=0&size=6` |
| Карточка, создание, изменение, мягкое удаление авто | GET / POST / PATCH / DELETE `/api/v1/cars` и `/{id}` |
| Выбор / создание владельца | GET / POST `/api/v1/owners` |
| Список / создание центра | GET / POST `/api/v1/service-centers` |
| Создание обслуживания | POST `/api/v1/cars/{carId}/maintenance-records` |
| История, фильтры и «Показать ещё» | GET `/api/v1/cars/{carId}/maintenance-records` |
| Детали, включая после перезагрузки | GET `/api/v1/cars/{carId}/maintenance-records/{recordId}` |

Раздел «История работ» предлагает выбрать автомобиль: общего endpoint истории всех автомобилей пока нет. Список автомобилей для выбора загружается со всех страниц API.

История загружается порциями по 5 записей. Фильтры применяются на сервере: `q` (название позиции или PN), `dateFrom`, `dateTo`, `performerType`, `serviceCenterId`. Кнопка «Применить» начинает новую выборку с первой страницы. `SELF` сбрасывает центр. Некорректный диапазон дат не отправляется. Сортировка задаётся backend: дата обслуживания и ID по убыванию. Количество записей и общая сумма берутся из ответа сервера.

## Формы и ограничения

- Для обслуживания выбирается существующий сервисный центр по названию и адресу. Его можно создать в разделе «Сервисы»; UUID вручную вводить не нужно.
- Дата обслуживания не в будущем, пробег — целое неотрицательное число, минимум одна позиция.
- PN показывается только для PART; пустое значение отправляется как null. Для WORK PN всегда null.
- Предварительная сумма считается в целых копейках (BigInt), итоговая сумма берётся с сервера.
- Предел суммы одной позиции в интерфейсе — 999 999 999,99 ₽ для точной передачи копеек в JSON.
- Запись обслуживания не меняет текущий пробег авто — так работает Java-сервис.
- В PATCH автомобиля VIN неизменяемый; уменьшать пробег нельзя. Очистка госномера не предлагается: null на backend означает «не менять».
- Документы, напоминания, фотографии автомобилей и авторизация пока не подключены. Вместо фотографии используется нейтральная иконка; «Мой гараж» в шапке не означает авторизованного пользователя.

## Стек и структура

React + TypeScript + Vite, React Router, TanStack Query, React Hook Form + Zod, Lucide, локальный шрифт Manrope. Зависимости зафиксированы в lockfile.

| Каталог / файл | Назначение |
| --- | --- |
| `src/data/` | Типы DTO и HTTP gateway |
| `src/components/` | Формы, диалоги, серверная пагинация и фильтры истории |
| `src/pages/` | Экраны приложения |
| `src/lib/` | Форматирование дат, сумм и пробега |
| `src/app-context.tsx` | Уведомления |

Проверка типов и сборка: `pnpm build`. Автотесты пока не добавлены по договорённости. Для production раздавайте `dist/` с SPA fallback на `index.html`, а `/api` проксируйте к Spring. `vite preview` — локальный просмотр сборки, не production-сервер.
